# OPTIMIST LUDO 2.0 — Online multiplayer Mini App

Рабочая сборка объединяет три игровые геометрии — CLASSIC, HEXA и ROYAL — с авторитетным серверным движком, комнатами, WebSocket-синхронизацией и Telegram Mini App. Каждая топология имеет собственные координаты, маршруты и домашнюю дорожку; общая логика игры и визуальный язык OPTIMIST LUDO остаются едиными.

## Уже подключено

- Фирменная нижняя панель хода: нарисованный CSS-кубик с корректными раскладками 1–6, плоским кубиком с чёткой раскладкой точек 1–6 и короткой 2D-анимацией; на телефоне кнопка остаётся по центру снизу с учётом safe-area. Вспомогательные действия оформлены компактными иконками, состояния кнопок и клавиатурный фокус доступны.

- Четыре самостоятельные векторные доски в `assets/boards/`: CLASSIC (светлый дуб), NEON (чёрный хром), ELITE (тёмный орех с золотом), MARBLE (мрамор и платина). Все SVG используют одну точную сетку 720×720 и остаются чёткими на Retina/HiDPI.
- Геометрия Classic: 52 клетки маршрута, четыре домашние дорожки, четыре базы и финиш.
- Отдельная пиксельная привязка стартовых лунок к изображению; цвета: синий — верх слева, красный — верх справа, зелёный — низ слева, золотой — низ справа.
- 12 персонажей-фишек: 8 героев (OPTIMIST, Лиля, Натали, Никита, Poison, Лена, Эльвина, Ксюша) и 4 маскота (кот, сова, хаски, енот); сжатые WebP-ассеты.
- Серверные броски кубика и проверка ходов для CLASSIC / HEXA / ROYAL: выход на 6, точный финиш, безопасные клетки, захват, блокировки, бонусные броски и пропуск после трёх шестёрок подряд.
- Персональный выбор персонажа в лобби и прямо за столом; выбранный образ синхронизируется с комнатой, а цвет команды остаётся отдельным.
- Живые фишки с анимацией перемещения/выбивания/финиша, компактным стеком, цветным свечением и подсветкой только разрешённых сервером ходов.
- Четыре полноценных векторных оформления игровой доски: NEON, CLASSIC, ELITE и MARBLE. Материалы, рамки, клетки, базы и центральная зона нарисованы отдельно для каждой темы; все четыре сохраняют одинаковые игровые координаты и правила.
- Кинематографичные игровые всплывающие эффекты для шестёрки, выхода фишки, захвата и финиша, плюс переключаемые процедурные звуки броска/хода/выбивания/победы.
- Быстрый старт в одиночку: на старте сервер заполняет все свободные места ботами, которые используют тот же авторитетный движок и те же правила. Друзья могут занять свободные места до старта.
- WebSocket-комнаты, повторное подключение, full-state sync и room-bound resume token.
- Текстовый чат комнаты и голосовые сообщения: удержание кнопки — запись, отпускание — отправка, смахивание влево — отмена. Голосовые передаются бинарным HTTP, не через WebSocket.
- Telegram Mini App auth через серверную проверку `initData`; локальный dev-auth разрешается только явным флагом `ALLOW_DEV_AUTH=1` вне production.

## Единая модель прогресса

Сервер хранит у каждой фишки только `stepProgress`. Зоны `base / track / home / finished` и локальный шаг выводятся из параметров выбранной топологии. Диапазоны: CLASSIC `-1, 0–50, 51–55, 56`; HEXA `-1, 0–71, 72–77, 78`; ROYAL `-1, 0–66, 67–73, 74`.

`Coordinates_Map.json` создаётся из канонических геометрий тем же проектом. Команды: `npm run export:coordinates` для одной карты или `npm run build` для SVG и карты вместе. Ручная правка сгенерированного JSON не требуется.

## Игровые режимы и геометрии

В лобби отображаются живые SVG-превью выбранной геометрии и четырёх тем. Персонажи и доски разрешаются относительно URL JS-модуля, чтобы работали в локальном запуске и во вложенных preview URL.

- CLASSIC: 2–4 игрока, 52 клетки общего маршрута, 8 безопасных клеток и 5 домашних клеток.
- HEXA: ровно 6 игроков, 72 клетки общего маршрута, 12 безопасных клеток и 6 домашних клеток.
- ROYAL: ровно 4 игрока, 68 клеток общего маршрута, 12 безопасных клеток и 7 домашних клеток.
- Все три режима поддерживают четыре оформления: NEON, CLASSIC, ELITE и MARBLE. Темы не меняют игровую геометрию. Правила закреплены в `RULES.md` и `EXTENDED-GEOMETRY-SPEC.md`.
- Все геометрии SVG работают в единой системе 720×720; размер фишки рассчитывается из шага своей клетки, а касание обрабатывается отдельной hit-area.
- Перемещение по нескольким клеткам анимируется через промежуточные координаты маршрута, включая вход в домашнюю дорожку.

Спецификация геометрии и сравнение открытых источников: `EXTENDED-GEOMETRY-SPEC.md`, `GEOMETRY-RESEARCH.md`.

## Запуск локально

Требуется Node.js 22.9+.

Для локальной проверки без токена Telegram:

```bash
npm install
cp .env.local.example .env.local
npm run start:local
```

Открой `http://localhost:3000`. Dev-auth включён только для локального режима. Внешний хостинг и BOT_TOKEN для такой проверки не нужны.

Для тестирования в обычном браузере без Telegram открой `.env` и установи:

```env
ALLOW_DEV_AUTH=1
NODE_ENV=development
```

Для production-подобного локального запуска можно использовать основной `.env` и `npm start`; локальная проверка выше проще и безопаснее. В этом режиме можно создать комнату в двух вкладках/браузерах и играть друг против друга. При локальном dev-auth имена/ID создаются браузером автоматически; в Telegram используются реальные проверенные данные Mini App.

## Production / Telegram

1. Создай бота через BotFather и укажи его токен в `BOT_TOKEN`.
2. Укажи точный публичный HTTPS origin в `ALLOWED_ORIGINS` (например, `https://your-app.example`).
3. Оставь `ALLOW_DEV_AUTH=0` и `NODE_ENV=production`.
4. В BotFather задай URL Mini App на этот же HTTPS origin.
5. Запусти `npm start`.

Не публикуй `.env` и не добавляй `BOT_TOKEN` в репозиторий.

## Проверки

```bash
npm test
npm run smoke
```

`npm test` выполняет unit-тесты геометрии, рендера фишек, движка, комнат, Telegram auth, reconnect/resume, голосового клиента/кэша и визуального контракта кубика/нижней панели. `npm run smoke` запускает реальный локальный HTTP/WebSocket сценарий: создание комнаты, вход двух игроков, запуск, бросок, ход, upload/playback голосового и reconnect с восстановлением состояния. Для smoke нужен установленный пакет `ws` (`npm install`).

## Важные границы

- Комнаты, resume-токены и аудиофайлы пока хранятся в памяти одного процесса. Обрыв WebSocket восстанавливается, пока процесс жив; полный рестарт процесса очищает незавершённые комнаты и голосовой кэш.
- Временный voice cache ограничен: 512 КиБ на файл, до 30 секунд, 8 МиБ и 40 файлов на процесс, TTL шесть часов. При заполнении старые файлы вытесняются.
- Реальную работу микрофона нужно проверить внутри Telegram WebView на Android/iOS: браузерные разрешения и поддержка MediaRecorder зависят от платформы.
- Полная проверка 2.0 должна включать `npm run build`, `npm test` и `npm run smoke`; результаты последнего CI-прогона публикуются в GitHub Actions.
- Доступны все 12 текущих персонажей и четыре самостоятельные векторные темы основной доски. Отдельные геометрически отличающиеся настольные макеты из промо-концептов пока не включены: на некоторых из них центральный логотип перекрывает игровые клетки.
- Auto-Pilot, постоянное хранилище партий, рематч и рейтинг остаются отдельными задачами и не входят в текущий релиз 2.0.

Подробности: `apps/backend/README.md`, `FREE-HOSTING.md`, `VOICE-MESSAGES.md` и `ROADMAP.md`.


## Векторные доски и мобильная разметка

В `assets/boards` лежат четыре независимые SVG-доски: CLASSIC (светлый дуб), NEON (чёрный хром), ELITE (тёмный орех и латунь), MARBLE (холодный камень и платина). Они используют одну 720×720 логическую систему координат, поэтому маршрут, безопасные клетки, домашние дорожки, базы и финишные якоря совпадают при любом размере экрана. Перегенерация: `node scripts/build-board-assets.mjs`.

Проект поддерживает три игровые геометрии: CLASSIC, HEXA и ROYAL. Для генерации всех векторных досок выполни `npm run build`.
